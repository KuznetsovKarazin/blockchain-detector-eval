# Prospective Slither execution adapter v1

This is tooling for a future external-B release. The current protocol, human review and inference gates remain closed. No real corpus scan or score is authorized by this directory. Only the 25 authored fixtures can execute through the separate synthetic commands. Software expectations are tool regression checks, not expert vulnerability labels or human semantic sign-off.

## Fixed behavior

Slither 0.11.6 / crytic-compile 0.4.2 runs seven explicitly registered detectors, in this order: reentrancy-eth, reentrancy-no-eth, reentrancy-unlimited-gas, reentrancy-benign, reentrancy-events, unchecked-lowlevel, unchecked-send. Informational results are included. All seven instantiated detectors and all seven completed result groups, and exactly one compilation unit, are required for success. Analysis is strict, with no partial results, skipped assembly, dependency/path exclusions or annotation suppression. Triage uses a fresh nonexistent database.

The proposed primary score is the binary union of root-attributed primary detector alerts (three reentrancy detectors or two unchecked detectors). Counts remain descriptive; this score is not a vulnerability probability. Broad reentrancy adds benign/events, as a separate secondary vector. Ties require the existing expected-tie workload metrics. Failed or unavailable analysis always has an empty score, never zero. All four per-file rows retain raw and canonical status plus the same trace hash.

Attribution uses the exact first finding element, the principal focus documented by the official Slither JSON schema. The selected detectors place a function definition first. Absolute and relative filename identities, and filename_used when present, must agree with the exact closure. filename_short is display-only. Unknown or ambiguous attribution fails the complete file; there is no search for a later recognized element. All source mappings are retained as normalized metadata plus a full finding hash. Import-defined inherited functions remain attributed to the import even if reachable through a root-derived contract. A root score of zero means no root-attributed alert, not that the root contract is safe. Imported-only alerts are counted separately.

These are prospective choices, not exact historical C3 execution equivalence: C3 excluded informational findings (making its nominal unlimited-gas mapping ineffective), retried versions until analysis success, and lacked root-only attribution. Binary union agrees with historical flag construction, but the execution and attribution policies differ. Human review must address these changes and detector/class meaning; unchecked return consumption/storage can suppress a tool alert without proving adequate failure handling.

## Compilation and runtime integrity

The original compiler-only plan and results are immutable. This worker reuses its exact ordered candidates, contexts and statuses, but creates a new standard-JSON configuration requesting ABI, AST, initialization/deployed bytecode objects and both source maps. The old compiler-only outputs are not advertised as directly usable by Slither. Missing required fields fail explicitly; fields are not fabricated. The first successful compiler fixes the version. There is one subsequent Slither attempt and no version fallback after analysis failure. Limits are 180 seconds shared per compiler/analysis attempt, at most five declared candidates, 2 GiB address space, bounded stdout/stderr and 7200 seconds total including per-file staging. Only frozen inline source contents enter the compiler; no URL, remapping, fetching or rescue candidate is permitted. CRLF and UTF-8 bytes are preserved.

A precompiled Crytic platform parses that compiler output without invoking another compiler/build. Installed files are checked against RECORD hashes and all 47 pinned wheels, with exact installed versions and no unexpected site-package files or symlinks. pip25.0.1 is an explicitly identified bootstrap package, RECORD/hash-bound but not one of the47 wheel anchors. Installer-generated RECORD/scripts are separately hash-bound. Three pinned wheels (eth-abi, eth-rlp, hexbytes) share six docs paths; installed shared bytes must match a pinned owner, every RECORD expected hash must match that owner’s wheel, and all owner hashes plus the actual matching owner are recorded. No arbitrary mismatched file is accepted. Interpreter identity is pinned. Isolated children use -I -B and a fresh pycache prefix, preventing reuse of stale cached bytecode. Own modules load exact source bytes rather than cached pyc. The child blocks nested processes/network and unrecorded source reads at the application level. These guards are not a kernel sandbox or protection against malicious runtime code; the interpreter standard library is the host runtime, outside the47-wheel inventory.

## Production admission and outputs

`preflight` calls the existing early admission API before any worker corpus source or training key read. `execute` requires that admission, a separate coordinator authorization with a caller-trusted SHA, exact bound code/policy/runtime/compiler plan, and then full `begin_scoring` integrity. Names/hashes record procedural authorization; they do not authenticate humans or grant permission by themselves. The prospective method configuration needs `slither_worker` with schema `external_B_slither_worker_config_v1`, exact `policy`, `code_sha256` from `code_files()`, and `{path,sha256}` references `runtime_inventory` and `compiler_plan`. All raw/canonical status mappings must also be frozen in the method configuration. This is a new required prospective configuration; current draft bindings cannot execute.

Authorization schema is `external_B_coordinator_execution_authorization_v1`, action `slither_scan`, authorized=true, coordinator_id, issued_utc, binding/release/worker/reference-event/runtime-inventory/compiler-plan SHA256s, and exactly `authorized_job_ids=["slither:reentrancy:0","slither:unchecked:0"]`. The full1998 fixed test frame is preserved. Primary IDs are `slither:CLASS:0`; secondary IDs `slither_broad:CLASS:0`; method slither, seed0, variants primary/broad_secondary. Production output is restricted to private `data/derived/...`, because raw compiler errors and finding descriptions may contain source text. Only normalized status/count/mapping metadata and hashes should be published. Primary static receipt fragments fit the existing orchestration slots; broad vectors are separate reporting input, excluded from the primary common-success intersection.

Config/source snapshots precede execution. Complete-run resume verifies the exact input/config/runtime/code and full output inventory; changed or incomplete output is refused rather than silently rescanned. Unavailable rows consume queue coverage and retain failure statuses. A run interruption does not manufacture scores or a complete receipt.

## Reproducible authored checks

From the repository root (replace PLAN_SHA with the printed digest):

```sh
.venv/bin/python -m pytest -q papers/security_evaluation/revision1/external_protocol/slither_worker_v1/test_worker.py papers/security_evaluation/revision1/external_protocol/slither_worker_v1/independent_review
.venv/bin/python papers/security_evaluation/revision1/external_protocol/slither_worker_v1/worker.py prepare-synthetic --out papers/security_evaluation/revision1/external_protocol/slither_worker_v1/authored_check_20261026_v1
.venv/bin/python papers/security_evaluation/revision1/external_protocol/slither_worker_v1/worker.py run-synthetic --plan-dir papers/security_evaluation/revision1/external_protocol/slither_worker_v1/authored_check_20261026_v1 --expected-plan-sha256 PLAN_SHA
.venv/bin/python papers/security_evaluation/revision1/external_protocol/slither_worker_v1/worker.py run-synthetic --plan-dir papers/security_evaluation/revision1/external_protocol/slither_worker_v1/authored_check_20261026_v1 --expected-plan-sha256 PLAN_SHA --resume
```

The fixture plan freezes source/code/runtime hashes, concrete positive/negative/import expectations and descriptive context cases before any actual compiler/Slither invocation. It covers modern/historical Solidity, root/import/inheritance, interface/abstract schema, CRLF/UTF-8, inline suppression, unchecked return contexts, compiler syntax failure and unavailable pragmas/imports. Expectations are never changed in response to results. Any failed expectation is retained and reported. Source/runtime changes require a new identified run, preserving the original snapshots and outputs.

Primary references: pinned installed detector/Crytic source and wheel bytes; official https://github.com/crytic/slither/wiki/JSON-output. Human semantic sign-off and any prospective inference amendment remain outside this software check.
